# 简历：四信号与可追问的项目经历

## 目标

写出一页简历，每条项目陈述都能追到自己的行动与证据。

## 讲授

课程的四信号是端到端交付、客户接触面、生产环境、可量化结果。它们是检查素材的角度；没有生产经验就说明训练或试点，不能为了四项齐全伪造一项经历。

项目句可以按“动作＋构建物＋业务上下文＋结果依据”组织。比如“为模拟报销场景建立预审 CLI 与回归集，覆盖 12 条虚构用例并验证幂等写回；未接真实企业数据”。它比“熟练掌握 Agent 技术”具体，也不会把规则实验包装成真实业务收益。

区分“我”与“团队”：自己定义了哪条规则、实现了哪个接口、定位了什么失败。用了 AI 生成代码，也应能解释关键设计、测试和局限；不能只把 Agent 的输出当成个人能力证明。

没有商业数字时，可用有口径的测试覆盖、处理耗时或边界数量，但必须写清环境与分母。验收通过率、准确率和客户效益是不同概念，不应互相替换。

## 实验

在 `work/evidence/08-resume.md` 写一句话定位、核心能力、项目经历、工作经历与教育背景。项目按背景、范围、本人行动、验证结果、复用资产展开；内容不适用时删去，不凑经历。

另附四信号表，把每条量化描述连接到报告或观察记录。选择一句项目话，连续追问三次“你怎么知道”，检查是否经得起核实。

## 验收

简历能在一页阅读范围内讲清最相关经历；数字有出处，个人贡献清楚。没有真实客户或生产证据时已明确标识。
