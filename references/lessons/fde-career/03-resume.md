# 简历：四信号、项目公式与训练营作业映射

## 目标

学生掌握 FDE 简历与普通工程师简历的本质区别，能把训练营六天大作业改写成简历上的五条能力证据，并完成本课小作业：写一份 FDE 简历。

## 讲授

**底层逻辑：招聘方扫简历时找四个信号。**有机构分析了一千份 FDE JD，得出结论：招聘方扫简历时会寻找——

1. **端到端交付**：你有没有从头到尾对一件事负过全责；
2. **客户接触面**：你有没有直接面对过客户或业务方；
3. **production（生产环境）**：你做的东西是真上了生产，还是只停留在原型或笔记里；
4. **可量化的结果**：你的结果能不能用数字说话。

讲师建议把一句话直接抄到简历文档的顶上，写简历时先看一眼，翻译成大白话是：「我有负责到底的态度，和给客户带来的真实改变。」要的不是技术多花哨，而是对结果负责的证据。**普通简历是技术栈导向的，FDE 简历是结果导向、工程导向、项目导向的。**

**动笔之前先对表：一千份 JD 里出现频率最高的技能。**Python、AI Agents、TypeScript、AWS、LLM，后面是 RAG、向量库、Docker 之类。注意 Agents 已经排到第二名——训练营五天用 Claude Code 或 Codex 做 Skills、MCP、跑 Eval 的经历，对这个表基本全部命中。但要清醒：**关键词只能让机器筛简历时把你留下来，留下来之后靠项目经历打动人。**

**项目经历公式：动词 + 你构建的东西 + 客户上下文 + 量化结果。**

- Bad case：「我协助客户搭建了数据管道。」——怎么协助的？搭建到什么程度？不知道。
- Good case：「我为一家 500 强零售客户负责端到端的数据管道部署，统一了 12 个分散数据源，首次洞察时间从三个月降到三周。」——动词是「负责」，对象确定，客户画像确定，结果里有数字。

另一个细节：用「我」，不要写「我们」。面试官一看到「我们」，第一个问题就是「这里面到底哪部分是你干的」。与其被拷问，不如写清楚：就是我干的。

**国内面试场上的两个血案（一手面经）。**

1. 简历上写了 agents、写了 RAG，面试官一问，发现其实只是调了个 API——这是被面挂率最高的写法。写上的词必须经得起推敲和追问。agent 开发相关的面经市面上不少，面试前狠狠恶补。
2. 面试官问「你的代码能力如何」，答曰「主要是 vibecoding」。——AI 帮你写代码没有任何问题，训练营六天都是这么写的，但不能轻视 AI Coding 这门手艺，也不能放弃对传统软件工程的理解。我们做的不是 vibecoding（凭感觉瞎胡来），至少要称之为 **AI Coding，AI 辅助编码**：你必须能为每一行生成的代码负责。如果真的只会 vibecoding，作为 Delta 到了现场会露馅。

**FDE 简历骨架：五个区块。**

1. **一句话定位**：不要写「热爱编程」之类，要写「能够进到业务现场做 AI 落地交付的工程师」这个量级的话；
2. **核心技能表**：对照高频技能表，写你真会的（没有的后面补面经）；
3. **项目经历**：每条按五段式展开——业务背景、需求边界、方案选型、可量化结果、沉淀了什么可复用的资产；
4. **工作经历**；
5. **教育背景**。

注意顺序：**项目经历放在工作经历前面。**对 FDE 岗位，你交付过什么比你在哪儿待过更重要（除非你有互联网大厂之类的前置背景）。

**训练营大作业 → 简历的五条能力证据（讲师给好的映射）。**

| 天数 | 作业产物 | 简历写法 | 对应能力 |
|---|---|---|---|
| Day 1 | 需求说明清单、业务流程图 | 独立完成企业场景需求挖掘，明确三项范围边界 | 需求挖掘 |
| Day 2 | SOW | 将模糊业务诉求拆解为带验收标准的模块排期 | Scoping |
| Day 3 | Skills | 将业务规则封装为可测试的 AI 能力单元，附三项测试证据 | 能力封装 |
| Day 4 | 系统接入 | 完成企业系统的 MCP 和 API 集成，含权限与异常处理设计 | 系统集成 |
| Day 5 | Eval | 自建不少于十套用例的验收测试集，给出通过与否的量化结论 | 验收评估 |

**没有商业数据，量化什么？**三类数字你肯定有：

1. **测试集指标**：通过率、覆盖场景数；
2. **效率 / ROI 指标**：同类任务的人天对比，做完之前和之后差多少；
3. **边界指标**：处理了几类异常场景，设了几个人工兜底点。

讲师随口给的示范句：「这个项目的验收通过率 87%，覆盖了 12 类边界场景，其中三类设了人工兜底。」——没提钱、没提商业，但充分展示了工程判断力。**没有商业数字不丢人，体现能力不一定靠商业数字背书，要展示出你的判断力。**

## 常见误区

- 简历按技术栈罗列，而不是按交付结果组织；
- 写「我们」不写「我」——等着被面试官拷问分工；
- 写上经不起追问的 buzzword（agents、RAG 只调过 API）——被面挂率最高的写法；
- 自称「主要 vibecoding」——要说 AI Coding，并为每一行生成的代码负责；
- 以为没有商业数字就没法量化——测试集、效率、边界三类指标人人都有。

## 实验（本课小作业，课程原题）

**写一份 FDE 简历。**要求：五个区块齐全（一句话定位、核心技能表、项目经历、工作经历、教育背景）；项目经历按五段式展开，素材直接来自训练营 Day 1–5 大作业的五条能力证据映射；项目经历放在工作经历之前。写完之后**用四信号逐条自查**：端到端交付、客户接触面、生产环境、可量化结果，每条打勾或写明缺哪条、怎么补。

## 证据

简历真实存在、可检查；四信号自查表逐条有结论；能口头解释每一条项目经历里的量化数字是从哪来的（哪套测试集、哪个人天对比、哪几个边界场景）。
