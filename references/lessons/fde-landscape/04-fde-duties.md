# FDE 核心职责与 Solo 起步路径

## 目标

学生能列出 FDE 的核心职责清单，知道每一项对应解决什么挑战，并能说出 Solo FDE 从 0 到第一个案例的现实路径。

## 讲授

### 核心能力与职责

**1. 需求识别：观察，不是开会**。和一线实际操作者去问、去观察。开会时对方说的是准备好的话；潜藏的东西——他不想告诉你的、他没意识到的——才会真正影响 Agent 构建。做法可以是驻场：坐在旁边看整个业务流程，记录他需要获取哪些信息、信息怎么组织、存哪里（飞书还是微信直发）、有哪些小操作小习惯、内部怎么协作。只有这样，Agent 才可能是可用的生产级。

课程提醒：只按需求单实现功能的交付模式，容易漏掉现场信息。是否能持续观察业务，取决于项目预算、合作方式和团队安排。

**2. 工程能力：最稳固的基座**。系统集成、工具接入、Agent 编排与部署、数据清洗——包括面对"七老八十的古老系统"也能快速处理。对开发人员转行者：你见过真正好的软件架构，这是大优势——"它毕竟还是一个软件"。

**3. 生产级标准**。生产级 = 稳定性、大规模、经得起真实工作使用；不是"点个 Demo 让老板开心"。多次操作稳定输出，每一步**可审计、可回溯**。

**4. 评估与验证：直接涉及回款**。一开始就把 Agent 的目标定好，设置可靠的评估集、验证集，收集任务和单证，评估数据量是否够代表真实能力。这块没做好，客户验收时"我要试这个我要试那个"，会带来超长返工和成本——服务央国企长周期项目时尤其致命。FDE 以结果交付，评估验证是必须花心思的一块。

**5. 跨层沟通（people management）**。对老板拉近认知；对中层要让他们愿意掏心窝子讲出真实理解，同时梳理利益关系；对基层员工——如果他觉得你是派来取代他的，就不会好好配合。这部分原本是售前和销售做的事，现在 FDE 到现场，必须自己面对。

**6. 端到端对结果负责**。设定可衡量的目标、在真实环境中构建、推动组织配合、沉淀并反哺产品团队。具体职责应以目标团队的岗位与项目约定为准。

### Solo FDE 获客与起步

获客渠道：

1. **熟人亲戚朋友**：大部分人第一批案例来自这里。例：亲戚的厂 30 人、两个外贸员，帮他构建外贸 Agent——家里人放心你，容忍度也高；
2. **AI 和 FDE 社群**：观猹、OpenFDE 社区，同行密度高，能获取新信息甚至分包合作机会；
3. **自媒体 IP**：持续发专业内容，企业看到案例会来找你；
4. **垂直行业深耕**：技术没那么强但家里有能源、电商、跨境等行业资源，仍然是很好的机会——行业 know-how 一定程度上比技术更重要。

起步路径（从低风险开始建立信任）：

```text
你有认知的行业
→ 找到可观察的流程
→ 先用人工方式执行一遍
→ 再做自动化
→ 建立最小评估集
→ 从错误容忍度高的环节开始
   （老板是你亲戚，或工作流本身不关键：文书整理、跟单）
```

### 几个现场问答里的真话

- 文科零基础能不能入行？"我讲的内容你能听懂，你就能入行"；
- 非研发怎么判断产出是不是生产级？"你有行业 know-how，你就是老师，技术同事做的东西应该由你来判断"；
- 在校生怎么准备？观察身边在电脑前工作的人，问"你的步骤是什么"，想这些能不能用 Agent 实现。

## 常见误区

- "FDE 有标准答案"——没有。大厂在探索，Solo 团队在探索，企业自己也不知道最好的 Agent 长什么样；
- "工程能力是最重要的"——它是最稳固的基座，但需求和评估同样决定回款；
- "先做出完美的 Agent 再找客户"——路径恰恰相反，从错误容忍度高的环节开始建立信任。

## 实验

1. 征得一位熟悉的工作者同意，做一次约 30 分钟的观察访谈：他获取哪些信息、信息存哪、有哪些重复动作。在 `evidence/workflow-observation.md` 记录匿名角色、步骤、耗时、异常和信息缺口，请对方核对流程是否准确。没有合适对象时可回放自己的一次工作，标为自我观察；
2. 从观察记录里挑一个"错误容忍度高、流程可观察"的环节，写下：如果把这个环节交给 Agent，最小评估集长什么样（3–5 个测试用例）；
3. 检查你的获客渠道：熟人、社群、自媒体、垂直资源，四条里你已有哪几条？写下最现实的第一条路径。求职者可改写为一条接触目标团队的路径。

## 证据

一份可检查的观察记录、3–5 个测试用例，以及一条起步路径；存档记录文件路径和对方反馈。角色扮演只能标为演练，不能记成真实访谈。
