# CLI 工作流：从 SOW 到可运行原型

## 目标

把一项业务承诺落实到文件、命令和能复现的运行结果。

## 讲授

这里的 CLI 工作流，是用命令行编码工具组织开发；它与后面“把企业系统封装成 CLI”属于不同层次。前者帮助构建软件，后者成为 Agent 调用业务能力的入口。

按 SOW→SPEC→小步实现→验证推进。SPEC 要说明输入、输出、状态、接口、错误与验证方式。例如“超标单转人工”应落成：金额整数分、制度版本、比较运算、`manual_review` 输出，以及一条超过限额 1 分的用例。只画页面无法证明这一承诺。

把团队长期适用、模型不知道的约定写入项目指导文件，如“金额以分保存，预审不改变审批状态”。一次性任务放在当前需求中，避免指导文件堆成项目日志。让 Agent 修改前先读现有文件，完成一小步就查看真实输出和 diff。

## 实验

读取 `references/lab-guide.md`，初始化一个新的实验工作目录。先运行 `--help`，再分别运行故障基线和当前版本，保留两份 JSON 报告。

参考 `assets/templates/expense-spec.md`，在 `work/evidence/02-spec.md` 为“金额边界判断”写四部分：输入、规则、输出、用例；把 E002 与 E003 对照，解释等于限额与多 1 分的区别。为规则增加一条自己的变异用例，再运行评测。

在 `work/evidence/02-prototype.md` 记录实际命令、退出码、报告路径、版本与发现。预置故障切换是教学演示；只有自己修改过的内容才记为自己的代码改动。

## 验收

原型实际运行；能从 SOW 的一项承诺追到 SPEC、规则和用例。新增用例有明确期望，不能只贴“运行成功”。
