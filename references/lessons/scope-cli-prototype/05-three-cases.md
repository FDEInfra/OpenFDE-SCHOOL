# 三个实战案例：斯凯奇、奶粉 KOS 矩阵、银行信用卡客服

## 目标

学生通过三个真实交付案例，理解"准确率爬坡 + 驻场诊断 + 数据闭环 + 沉淀标准产品"的 FDE 交付形态，并能复述每个案例的北极星指标。

## 讲授

### 案例一：斯凯奇——电商素材的 AI 标注与智能套板

斯凯奇总部在美国、斯凯奇中国在广州，安踏在福建厦门，都是鞋服零售品牌。痛点：每年几千上万个 SKU 要上架淘宝、拼多多、京东、唯品会等货架电商（一个具体货号是一个 SKU，货号之上的款是 SPU）；各平台主图尺寸要求不一（比如有的 800×800、有的 800×700），详情页还越来越视频化。原来设计师用 PS 的镜像套板功能手动做，慢。

方案：用 AI 给主图、详情页、主图视频做标注，基于模板做智能套板。北极星指标是**准确率从 85% 提到 95%，一个月交付**。注意 100% 的交付不现实，目标就是从 85% 提升十个百分点。

过程是硬骨头：客户从模块、场景到验收状态提了大量 P0/P1 问题甚至质疑，团队（算法、数据标注、工程，由 Lyon 带队）进入客户现场驻场几个月，把上游 IT 部门到业务部门的需求流程摸清楚，把问题顺进客户的 workflow 里解决。方法上，把"看起来对不对"拆成明确的判断，用真实样本产生可复用依据，**每一次错误都对应到具体的规则和数据上**。

数据标注是模型进步的核心：一批客户数据几个 G 到几十个 G，团队自有数据达几个 T 级别；标注后分训练集和测试集做定向优化。特征要拆得很细——衣服有上身模特图、衣服细节，鞋有上模特图、正面、背面、鞋带等。不是一次冲刺，而是让规则、数据、评测反馈形成闭环。

结果：一个月内以 95% 交付斯凯奇；下一个季度，**同一个产品能力迁移到安踏，拿下安踏的 POC 并完成交付**。这个 FDE Sprint 沉淀下来的是一个标准产品，再拿它去拓展下一个客户——从交付结果到同行参照、再到下一次诊断，形成闭环。Lyon 的金句："我们面对的从来不是生成的问题，而是交付的问题。"

### 案例二：头部奶粉品牌——小红书 KOS 矩阵

行业背景：全行业有十多万个 KOS 账号（KOS = 关键意见销售）、相关笔记约两百万篇，面对的是 1.1 亿规模的母婴人群市场。项目把这个品牌的账号**从 2000 个做到 6000 多个**。

链路：导购人设 → 选题库 → 合规 skill 初审 → 人工二审发布。核心难点是**广告法合规和品牌合规**，在此之上提升单周、单天的笔记产能。这是百万级项目，涉及招投标；FDE 驻场两到三个月，摸清导购部、营养专家部等不同部门的诉求后梳理需求再上线。（答疑补充：矩阵账号的手机号由客户提供。）

### 案例三：银行信用卡 AI 客服

场景：在社媒运营和企业微信社群里，用 AI 做信用卡的售前、售中、售后客服；消费者在企业微信或小程序问到产品相关问题时，能多轮对话、准确回答权益和产品点。

技术主线：海量商品信息走 RAG 处理，目标**95% 准确率**。从最初约 70% 爬到 95%，历时约一年，项目从 2023/2024 年启动，分很多期迭代至今。

答疑中补充了关键技术细节：这个项目曾踩坑踩到客户要退款。传统 RAG（向量化 embedding 后逐 chunk 检索）表现有限，最终方案是 **agentic RAG**——加 reasoning 推理，做大量意图槽位，多轮对话命中意图槽位后再推理。当时 LLM Wiki 还没出现；现在 LLM Wiki 也能解决一些复杂场景，单轮还是多轮对话要看具体需求选型。另有学员问金融合规下用什么模型，Lyon 推荐国内模型"Kimi K3"（音译存疑，字幕作"K三"）。

### 三个案例带走的共性

- 北极星指标都是数字：95%、95%、账号数与产能——没有一个是"体验更好"；
- 最后一段准确率爬坡靠驻场 + 数据标注闭环，不靠换更强的模型硬冲；
- 交付沉淀为标准产品后可迁移同行（斯凯奇 → 安踏），第二单不再是纯定制；
- 内容类项目里，合规是生死线，且被做成流水线环节（skill 初审 + 人工二审）。

## 常见误区

- "85% 和 95% 差不多"——最后十个点的交付难度极高，恰恰是 FDE 驻场的价值所在；
- "Demo 效果好就能交付"——客户提的是模块级、场景级、验收状态级的问题清单，要逐条对应到规则和数据；
- "合规是发布前扫一遍"——它被做成流水线的固定环节（初审 skill + 人工二审），不是事后补丁；
- "准确率上不去就换模型"——这个案例的答案是把传统 RAG 升级成加推理、加槽位的 agentic RAG，并且靠一年的数据闭环磨出来。

## 实验

1. 任选一个案例，画出它的四格图：现状人工流程 → AI 介入点 → 量化指标 → 验收方式；
2. 为你自己的场景设计数据闭环：错误样本如何回流成规则或训练数据？写出三步；
3. 列出你目标行业的三条合规红线，并写出初审环节可以怎么自动化（对应案例二的 skill 初审 + 人工二审）。

## 证据

学生能复述三个案例各自的北极星指标和爬坡区间（85%→95%、2000→6000 账号、70%→95%）；能说清斯凯奇案例里"数据标注—训练—评测"闭环怎么跑；能解释"我们面对的从来不是生成的问题，而是交付的问题"。
