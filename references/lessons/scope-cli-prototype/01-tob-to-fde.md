# 传统 toB 交付链路与 FDE 铁三角

## 目标

学生能画出传统 toB 的完整交付链路，说清 FDE 在 AI 时代爆发的三大变量，并能拆解商务型、产品型、工程型 FDE 铁三角的分工。

## 讲授

**传统 toB 是怎么交付的。** toB 是"两套组织共同交付一个结果"。供应商侧的链路是：品牌与市场部 → SDR（电销、打 cold call 拿线索）→ 销售 → 售前/解决方案架构师 → （视情况招投标）→ 项目经理与产品算法 → 客户成功与客服。客户侧则由业务部门、采购部门、IT 部门（部分客户还有数字化部门）共同决策；有的需求由采购和 IT 发起，有的由业务部门自己找供应商发起。

两个要点：其一，售前/解决方案架构师的核心动作是做方案 PPT——做过什么案例、有哪些 logo、能解决什么需求，top down 地讲；其二，在当前市场环境下，百万级的 B 端项目主要靠销售自己的存量资源和客户信任关系获客，品牌、市场、SDR 转入线索的漏斗转化率并不高。

**FDE 落进 toB 公司的位置。** 传统 toB 公司不可能全员 FDE 化——它必须保留打造自己标品基座的团队。实践中的做法是把 FDE 放到销售、售前或产研其中一个环节，而越来越多的团队摸索出的现状是：**把 FDE 放到产研团队承接**。

**FDE 爆发的三大变量。**

1. **AI coding 变量**：销售、售前、产品都会 vibe coding 做 Demo 了。Lyon 提到 OpenFDE 社群里有的老师每天 token 消耗量达几亿甚至上十亿。人人都懂点技术，团队就越来越 FDE 化。
2. **客户需求变量**：客户老板自己都在用 ChatGPT、豆包（比如年营收五千万左右的老板），但通用模型改不了他现有的业务工作流。模型到客户业务场景之间的"最后一公里"需要 FDE 来完成。
3. **OPC 供给变量**：一人公司、自媒体、To C 产品的供给越来越多，但能变现的路径有限，大量人希望向 FDE 转型。

**铁三角。** 由此形成 FDE 的最小作战单元：商务型 FDE（偏销售、售前、客户成功，负责搞定人、搞定客户复杂的组织架构）、产品型 FDE（偏项目经理、设计，负责做 Demo、整体拉通、把需求沉淀到产品）、工程型 FDE（偏算法、研发、测试，负责把 Demo 稳定地产品化—— vibe coding 出来的代码出 bug 了要有人能修）。

**嘉宾张青（音译存疑）的补充：FDE 要拆成三层概念来讨论。**

1. **作为角色的 FDE**：到客户现场厘清需求、收集业务上下文，把杂乱需求快速变成能运行的 Demo 乃至 MVP，最终完成产品化工程化交付。这个角色借助 AI 增强，可以把传统需要销售、售前、项目经理、产品经理等 4–5 人团队的事，用"一个人 + AI"解决，近似 One Person Team。
2. **作为服务模式的 FDE**：在客户现场挖掘那些隐藏的、需要被萃取的痛点和上下文，快速收集现场反馈——相比团队间大量上下文转接，项目成本直线下降。
3. **本体（ontology）实施环节的 FDE**：做的大多是咨询工作——收集业务流程、关键数据、做数据清洗和业务再定义。中国绝大部分企业还没到能上本体的阶段；对本体感兴趣最集中的是车企，而主机厂没有小客户。小企业里看起来像本体的东西，实际往往是一个 LLM Wiki。

**FDE 与解决方案架构师的边界。** 解决方案的核心能力是"翻译"：把客户业务需求翻译成技术团队可落地的 SPEC/需求说明书（一般写到 MRD 或 BRD，PRD 交给产品经理）。它的两个产出是：沉淀标准解决方案提升销售转化率、把共性需求沉淀进产品需求池。交付物最终是 PPT。FDE 也做翻译，但面向部署和交付：场景在客户现场而非办公室，交付物是能在客户实际场景用起来的产品，至少是指导后续迭代的 SPEC。张青观察到的趋势：解决方案架构师对 Demo 产出的要求越来越高、对 PPT 的要求越来越低——"不能靠 PPT 火，要靠 Demo 火"。

## 常见误区

- "FDE 就是把公司的 AI 产品拿到客户现场用起来"——这只是一部分，核心是挖掘客户工作流里的真实需求；
- "甲方会因为你是 FDE 交付就在技术标里给高分"——嘉宾明确表示，截止课程时未见过任何标书把 FDE 交付方式、铁三角人数、资质年限写进评分；FDE 的价值体现在成本控制和盈利率，不改变甲方的验收流程（那是组织治理和合规问题）；
- "非技术背景做 FDE 没机会"——可以做产品型 FDE，往售前解决方案和 Demo 方向走；
- "售前岗位会被 FDE 吞并"——有一点趋势但并不明朗，两者能力要求最终殊途同归。

## 实验

1. 画一张传统 toB 交付链路图（供应商侧六个环节 + 客户侧四类部门），并标出 FDE 最可能切入的三个位置；
2. 选一家你熟悉的 toB 公司，判断它若设 FDE 岗位更可能放在销售、售前还是产研，写出三条理由；
3. 用一句话向 Agent 解释"为什么 toB 公司不可能全员 FDE 化"，让 Agent 只回答"对/不对/哪里不对"，不接受补充作文。

## 证据

学生能不看笔记复述：toB 供应商侧链路的六个角色、FDE 爆发的三大变量、铁三角三型各自的分工；能说清"角色 / 服务模式 / 本体实施"三层 FDE 概念的区别。
