# 记忆与持续服务：可见进度和预期管理

## 目标

定义一个有边界的记忆需求，并说明交付后怎样持续管理变化。

## 讲授

陈宏以 MemU 项目讨论 Agent Memory：不同应用要记住的内容与有效期不同。陪伴应用可能关心偏好，编码助手可能关心项目约定；“多存一些内容”不是设计目标。要从后续任务反推为什么记、何时读、谁能改以及怎样失效。

还要区分会话上下文、项目状态、业务知识与用户偏好。报销批次处理到哪属于状态，模拟住宿限额属于制度，不能因为用户说“以后都按这个报”就永久覆盖企业规则。过期记忆或错误检索也应进入评测。

嘉宾强调客户信任的四个动作：持续沟通、进程可见、风险前置、把技术问题翻译成业务语言。它们不等于始终报喜；及时展示失败与替代计划，才能避免把改动拖到验收时才暴露。

## 实验

在 `work/evidence/05-memory-plan.md` 选一项确有必要的记忆，写入条件、读取时机、来源、保留期限、修改与删除办法。再写一条过期或错误记忆的用例，期望系统澄清而不是盲目沿用。

制作一页周报：已完成证据、当前阻碍、对业务的影响、可选路径、需要谁在何时确认。不填不存在的客户反馈，不加入不必要个人信息。

## 验收

记忆计划由任务需要驱动，不把原始客户对话整段长期保存；周报能让业务使用者理解当前进度与风险。生成本课程证据卡，保留真实部署与使用效果的未验证项。

## 降级与下一步

无记忆平台时用脱敏 JSON 模拟读写，标明只是设计验证。完成后可到 Demo Day 课程检查展示、复盘和验收证据。
