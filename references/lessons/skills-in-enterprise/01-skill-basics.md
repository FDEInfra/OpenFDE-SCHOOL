# Skill 是什么：渐进式加载与值不值得封装

## 目标

学生能向外行讲清 Skill 是什么、它和提示词与智能体的关系、渐进式加载为什么是关键创新，并能用「省时间 / 提升体验 / 省钱 / 赚钱」四类标准判断自己身边哪些场景值得封装。

## 讲授

**Skill 是什么。** 一个说明书、工具包，或者一份最佳实践。我们把重复性的、枯燥的、或者已经被验证有效的做法交给智能体，让它拿到我们的经验帮我们干活。雾明老师的比喻：像《笑傲江湖》里把武功传给别人；装一堆别人的 Skill 则像吸星大法。另一个更准确的比喻是英雄联盟：英雄相当于智能体，英雄的技能相当于装的 Skill——同样的技能给任何人安装使用，效果几乎一样（同样的模型、同样的技能）。

**发展时间线。** Skill 在 2023 年就有了雏形；2025 年 10 月被正式提出（逐字稿音译为「SR B G」，存疑）后开始被重视；2026 年初大爆发。

**Skill 的三种来源。** 一是下载别人的；二是下载后发现不好使，改造一下；三是原创。多数人 Skill 搞得不多时主要靠下载，但网上高质量的 Skill 还很缺——下载一堆别人推荐的，可能经常用不着，用不着还占上下文。所以必须有能力改造别人的、最好有能力创建自己的。

**一个 Skill 长什么样。** 最关键的是一个文件夹里的 skill.md，它分两部分：

1. **元信息**：名称和描述。描述要写清楚什么时候使用、有哪些功能；
2. **正文**：具体干活的时候该怎么干。正文可以引用同文件夹里的其他文件（子文档、脚本、素材）。

**最大的创新：渐进式加载。** 智能体启动时只加载已安装 Skill 的元信息，清亮、随时可触发；触发某个技能后才加载 skill.md 的正文；文件夹里可能有很多东西，智能体只根据当前对话动态加载最需要的内容。这样上下文控制得非常好。想直观理解，可以把 Anthropic 官方的 Skill 仓库拉下来看它的结构——它绝不是「一个 Markdown」那么简单，里面有子文件甚至脚本。

**Skill 能干什么（三个典型用途）。**

- **内容生产**：讲师自己的 PPT 就是 AI 做的——用 AI 输入法口述备注，再生成配图直接贴入；
- **文档问答**：把一个产品的文档、用户说明、常见问题封装成 Skill（例子里叫「小智」），用户直接提问，描述匹配上就加载技能、自动读资料回答，人不再需要翻用户手册；
- **内部系统自动化**：企业内部系统手动操作很低效，封装成 Skill 后不用打开页面，数据查询、提交报销都能全自动完成。大厂里大多数主流平台基本都已可以通过 Skill 全自动操作。

**Skill 和提示词的区别。** 只有提示词，分享不方便、难以共享；网页上定义的智能体（如扣子）每次用要找到网页、切来切去，多智能体协作更麻烦。而一堆 Skill 可以灵活组合——讲师自己的知识库就是例子：参加大会用录音卡录下、看前沿视频文章，都通过 Skill 转文本、校对、回流到知识库，做分享前再让 AI 用这些高质量内容做扩充。

**「提示词过时了」是误导。** 提示词工程之所以叫工程，绝对不只是写提示词。它包括需求挖掘、复杂任务的拆解（怎么拆、为什么这么拆）、流程编排、分支判断、异常处理，以及搞 CLI、搞 MCP、搞知识库、感知大模型的能力边界。只要人的表达能力没提升、场景没挖掘出来，AI 就一定用不好。哪怕未来 Skill 这种形态过时了，你的场景沉淀依然有效——没有白走的路。

**哪些任务值得封装。** 上来就搞是错的，尤其做 FDE：先想清楚这东西有没有价值、是不是真痛点、用户会不会付费——很多人用 AI 快速搞出软件却卖不出去，不是技术不行，是伪需求。值得封装的四类：

1. **帮你省时间**：老是重复、不想干的事（如老师的报告审核、论文格式校对）；
2. **提升工作体验**；
3. **帮你省钱**：本来要花钱的，现在不用花了；
4. **帮你赚钱**：解决别人痛点、把一个行业的最佳实践做出来，别人愿意付钱。

## 常见误区

- 「Skill 不就是一个 Markdown」——它是一个文件夹，里面可以有多个 Markdown、脚本和素材；
- 「提示词过时了，学得晚就可以不用学」——提示词工程是需求挖掘+任务拆解+编排，不是「加个例子」；
- 「下载一堆别人推荐的 Skill 就能变强」——用不着的 Skill 白白占上下文，改造和原创能力才是分水岭；
- 「先搞出来再说」——先判断是不是真痛点、用户会不会付费，伪需求做得再快也卖不出去。

## 实验

1. 把 Anthropic 官方 Skill 仓库拉到本地，挑 2–3 个 Skill，记录每个 skill.md 的元信息怎么写、正文引用了哪些其他文件和脚本；
2. 列出你工作/学习中 5 个重复性场景，用「省时间 / 提升体验 / 省钱 / 赚钱」逐一归类，选出最值得封装的 1 个并写下理由；
3. 用一句话向 Agent 解释「渐进式加载」，让 Agent 只回答「对 / 不对 / 哪里不对」，不接受补充作文。

## 证据

学生能不查资料说出：skill.md 的两部分结构、渐进式加载的三个阶段（启动载元信息→触发载正文→按对话动态载文件）、Skill 的三种来源；并交出自己筛选出的 1 个高价值场景及归类理由。
