# Skill：经验封装与渐进式加载

## 目标

理解 Skill 的结构与触发机制，选出一个值得封装的工作场景。

## 讲授

雾明把 Skill 解释为一份可交给智能体使用的说明书、工具包或最佳实践。它能封装已验证的做法，但不能自动补齐业务判断，也不能保证不同模型得到相同结果。

按 [Agent Skills 规范](https://agentskills.io/specification)，基本单元是包含 `SKILL.md` 的目录，文件由元信息与正文组成。元信息说明技能是什么、什么时候使用；正文放工作方法，按需引用脚本、参考与素材。一个简单 Skill 也可以只有一个文件，不为显得专业而制造层级。

渐进式加载的直觉是：先看到目录卡片，匹配任务后读操作说明，需要时再读附属材料。具体客户端怎样发现、加载或截断内容，要查对应版本；不能把某个工具的长度限制当作所有 Agent 的规定。

判断值不值得封装，先看重复程度、错误成本、使用频率与输入是否稳定。省时间、改善体验、节约成本、创造收入是课程的四个价值视角，最终都要落到一个使用者和一条真实动作。

## 实验

阅读本校 `SKILL.md` 与 `assets/expense-precheck-lab/SKILL.md`，在 `work/evidence/03-skill-choice.md` 标出元信息、正文、按需资源三个位置。再列出自己的 5 个重复场景，选择一个，写清输入、使用者、预期产物和不适用范围。

例如“帮财务处理一切”过宽；“对一条完整的模拟报销记录生成带规则依据的预审建议”更容易检验。

## 验收

能解释一个 Skill 如何被找到、如何开始工作、何时读取参考；选定场景有边界，不只是一句“提高效率”。
