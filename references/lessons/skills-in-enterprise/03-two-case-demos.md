# 两个案例：文章解读与系统预审 Skill

## 目标

实现一个可运行的 Skill，比较“写了说明”与“完成工具执行”的差别。

## 讲授

文章解读案例的输出包括总结、要点、与读者工作相关的启发、批判性检查和延伸问题。读者背景能改善相关性，但延伸观点必须与原文事实分开；模型提出了问题，并不意味着作者犯了错。

报销案例则把 Skill 接到 CLI。Skill 负责识别任务、选择步骤、解释结果，CLI 负责参数和调用，服务端负责权限与数据约束。仅在正文里写“不要付款”，不足以代替服务端禁止付款的能力边界。

对 CLI 的安装与发现，课程强调减少用户的手工拼接，并用 `--help` 获取当前能力。落到实际项目，要说明可信来源、版本与依赖，沿用已有授权；不能因 Skill 缺少工具就随意下载未知脚本。本校实验随包提供，无需联网安装。

## 实验

选择一路，在 `work/skills/` 创建自己的 Skill 目录，文件名使用 `SKILL.md`。

文章路线：用自己提供的一篇可使用文章，试跑普通概括和有任务背景的解读；各抽取两条可核对断言，回原文确认。系统路线：参考 `assets/expense-precheck-lab/SKILL.md` 和 `references/lab-guide.md`，启动模拟服务，再让 Agent 查询 E003 与 E004，检查是否执行了 CLI 并说明依据。

在 `work/evidence/03-trials.md` 保存 3 次输入、实际输出、观察到的问题和调整。无须为了凑数编造 bad case；没有发现问题就写“本次未发现”，再扩大覆盖。

## 验收

Skill 文件存在并至少完成一次实际调用；系统路线含真实命令与返回，文章路线含原文核对。未调用工具时不能写系统已接通。
