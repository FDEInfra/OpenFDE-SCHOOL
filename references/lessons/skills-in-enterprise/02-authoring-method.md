# 创建方法论：先定义输出，再反推输入

## 目标

学生掌握创建高质量 Skill 的标准流程——先定义输出、反推输入、捋清步骤、建立测评，并能识别「输入与真人真实场景不一致」这类最隐蔽的失效原因。

## 讲授

**最大的困难不是技术，是把模糊想法变成具体文档。** 一位做资产评估的朋友跟讲师说「模型好强，我感觉无敌了」，却说「我要搞一个资产评估的 Skill，我不会搞」。讲师的引导方式是连续追问：资产评估产出的报告长什么样？分哪几部分？每部分怎么推出来的？评估依据是什么？资产评估师本人是怎么评估的？——你光有一腔热血、光看到正片，一定搞不好。这位朋友把输出定义清楚、输入捋清楚、最佳实践捋出来，打磨几版之后，接一单能挣几千块钱。

**高质量 Skill 的两条来源路径。**

1. **AI 专家 + 采访行业专家**：AI 专家懂模型和 Skill 的调法，但不懂业务，去采访业务专家把经验捋出来。瓶颈是：你采访不到最顶尖的专家，模型可能 70 分、专家 80 分，调出来的 Skill 上限约 80 分；
2. **行业专家自己梳理**：专家本人懂业务，再学一些 Skill 技巧，自己测得满意，直接就是 90 分，别人挑不出毛病。表达不清楚时，可以请 AI 专家或程序员帮忙捋清输入输出和步骤。

最好两者合作，这和 FDE 的大逻辑相似。

**两种创建方式，推荐第二种。** 一是对话很多轮之后让 AI「帮我创建一个 Skill」——对话长了前面会被压缩，造成信息损失，而且上下文长时模型能力会下降；二是自己先想清楚，直接把逻辑说清楚让 AI 创建。对话轮数不多时第一种也可以用。

**Skill 里放什么。** 只放三样：什么时候触发（以及什么时候不触发，写清楚免得 Skill 多了互相搞乱）；关键步骤；干这件事需要、但模型训练里没有、连网都搜不到的知识。不需要的不要什么都往里放。另外，实际使用中发现的 bad case 要不断沉淀进去——讲师做公众号摘要 Skill 时发现：摘要里带出一个不知名产品名，转发卡片时别人以为是广告就不看了。于是加一条规则：出现不那么知名的产品名就不要写进摘要。失败的经验要不断累加。

**核心方法论（讲师自称「这一页最关键」）：**

1. **先定义输出**：输出都不知道，后面没得搞。输出分哪几部分、每部分怎么推理出来、不同部分之间什么关系；
2. **反推输入**：有了输出才能判断输入完不完整、能不能再加点什么让效果更好；
3. **捋清步骤**：几个步骤、为什么有这几步；
4. **定性或定量测评**：改完怎么知道变好了？你必须有测评集和打分标准。别人不懂你的业务，没法替你评估。

**真实 case：员工打分 Skill 为什么失效。** 大厂里有人做了一个给员工材料打分的 Skill：输入文档+评分标准，输出分数。结果智能体打的分和人工打的分差异很大。排查发现，问题不在 Skill，而在输入假设错了——真人打分时不只看文档：

- 文档太长，人精力不集中会漏掉关键东西；
- 现场有答辩，会说出文档里没有的、或被忽略但被强调的内容；
- 不同评委经验不同：计算机专业还是外国语专业、是不是喜欢逻辑强的人，都会影响分数。

所以要让机器打分接近真人，输入必须是「文档 + 评分标准 + 现场听记 + 评委的主观经验」。做 FDE 一定要有程序化思维：捋清楚实际情况和你理想的状态是不是一致，而不是想当然地认为「有个标准、文档一打分就完事」。

**Skill 效果三要素。**

1. **模型**：创建和使用 Skill 时模型好，效果就是好；
2. **输入准确完整**：输入错误或不完整，效果依然不好；
3. **反馈迭代**：进化的前提是你能给出反馈、知道哪里好哪里不好。企业里要边用边挑毛病、主动找用户拿反馈——讲师的平台上百个用户，一个人反馈一个问题，优化进 Skill 后所有人受益。

上下文工程的警示：每个环节 10% 的偏差，多个环节串联后可能放大到 20%–30%，越自动化效果越差，还浪费时间和 token。

## 常见误区

- 「我改完了，问别人我改得好不好」——别人不懂你的业务，测评集必须自己建；
- 「有文档+评分标准就能复刻人工打分」——真人决策用的信息远比文档多，输入要对齐真实场景；
- 「对话聊完顺手让 AI 生成 Skill」——长对话被压缩后有信息损失，想清楚再直接创建；
- 「别人给我的 Skill 提意见是批评我」——用户反馈是全体用户的经验增量，应该主动要。

## 实验

1. 针对 lesson 01 选出的场景，写「输出定义」：输出分哪几部分、每部分怎么推理出来、部分之间什么关系；
2. 反推输入清单：列出真人做这件事时实际用到的全部信息源，并标注哪些最容易被漏掉（对照员工打分 case 的思路）；
3. 写出步骤草案，并为它预设至少 2 条可能发生的 bad case 及应对规则。

## 证据

交出一份「输出定义 + 输入清单 + 步骤草案 + bad case 预案」的完整草稿；能讲清员工打分 case 失效的三类原因（文档注意力、现场信息、评委偏好），并说明自己的场景里对应的「现场答辩信息」是什么。
