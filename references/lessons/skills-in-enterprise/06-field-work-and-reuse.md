# 现场工作：从单个 Skill 到可复用交付

## 目标

把 Skill 放进售前、交付与采用三个阶段，并区分可复用能力与客户专属信息。

## 讲授

瑞老师用一线日常说明：FDE 的工作包括对齐进度、实现与集成、向产品反馈，再帮助客户学会使用。上线之后还要完成知识转移，让业务方能够持续运转，而不是只留下一个工具包。

课程的“碎石路变柏油路”指：在客户现场先解决具体问题，观察多次出现的共同约束，再提炼成平台能力。复用需要验证，不能把某客户的特例直接作为所有人的默认制度。客户原始数据、凭证和未经授权的材料，也不属于可抽取资产。

一线常见的 RAG 与 NL2SQL 分别解决知识检索问答与结构化数据查询。前者要核对检索依据、时效和引用，后者要限制访问范围并检查查询口径；都不等于把问题直接发给模型。选型从任务、数据形态与风险出发，不以工具是否热门决定。

## 实验

在 `work/evidence/03-adoption.md` 写一张交付计划：售前怎样展示边界，实施怎样验证，培训怎样让一位使用者独立完成核心动作。列一项可能来自 RAG 的规则查询和一项结构化统计，说明差别与权限。

为自己的 Skill 写复用表：可共享的流程、必须参数化的制度、必须删除的数据。设计一个新使用者的第一次任务，实际观察一次操作并记录卡点；做不到时保留待验证项。

## 验收

Skill、评测、使用说明三者对应，且有明确的业务负责人和下一次反馈入口。学生能说明第二个客户接入前还需验证哪些前提。

## 降级与下一步

无真实使用者时让导师按说明复核，不记录虚构的采用效果。课程证据卡可以标为完成训练；真实采用仍需补齐。接第④课时先确定接入的一条最小链路。
