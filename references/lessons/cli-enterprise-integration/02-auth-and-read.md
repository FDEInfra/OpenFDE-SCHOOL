# 先接认证与读取：最小可观察链路

## 目标

完成一次能区分认证失败、资源不存在与业务结果的读取。

## 讲授

课程建议先跑通登录和高频查询，再铺开接口。读链路也有前提：谁有权看哪些数据、凭证怎样获得和撤销、输出与日志可以保存什么。真实系统应使用受支持的认证流程；不能以抄取他人 Cookie 替代授权。

CLI 的基本链路是解析参数→读取配置→构造请求→服务端鉴权→业务处理→输出。凭证正确只说明身份通过，不代表拥有所有资源；返回空列表也不能自动解释为企业没有数据，可能还有分页、筛选与权限口径。

配套实验仅有公开教学标记，不能用作生产认证设计。它让学生观察 401、404、200 的差别：缺标记是 401，未知单号是 404，有效查询才返回业务结果。

## 实验

按实验指南启动本机服务。在第二终端先不设置教学标记执行 `list`，记录 401；设置标记后再次读取，应取得 12 条虚构记录。再查询未知单号与 E003。

在 `work/evidence/04-read-trace.md` 记录命令、状态码、记录数、制度版本和错误定位。画出请求各层经过了什么；不要复制真实凭证进证据。为真实项目另写分页与数据范围检查办法，本实验单页数据不能证明分页已经实现。

## 验收

存在真实 HTTP 读取输出，能区分环境、认证、资源与业务层；E003 的超标结果不是根据 200 状态码猜的，而是读到了 `decision`、`rule` 与 `evidence`。
