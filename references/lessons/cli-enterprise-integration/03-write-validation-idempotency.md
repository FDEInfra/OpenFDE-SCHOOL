# 写入：服务端校验、幂等与责任边界

## 目标

完成一次模拟写回，并证明重试不会重复产生记录。

## 讲授

把网页操作改成 CLI 时，容易遗漏原来在前端实现的格式、状态和幂等检查。应把关键约束放到服务端：任何调用入口都可能绕过客户端，Skill 中的提醒也不能承担访问控制。

写操作先明确对象与影响。预审建议、提交审批和付款是三种不同能力，不能因为都叫“处理报销”就合成无边界命令。课程建议按业务任务聚合接口；聚合后仍需保留各步骤的失败与恢复语义。

幂等表示同一业务动作重试时不重复改变状态。网络中断后，调用方可能不知道第一次是否成功，所以要沿用业务幂等键并查询状态；每次生成一个新键并不构成幂等。跨系统部分成功，还可能需要补偿或人工处理。

## 实验

依照实验指南，为 E003 保存模拟复核 payload，展示写入范围后执行 `write-review`。重复相同命令，比较两次 HTTP 状态与 `replayed`，查询复核列表确认只有一条。

再做两个反例：同一键改内容、同一单据换键再写。记录 409；不要改状态文件强行通过。在 `work/evidence/04-write-proof.md` 保存写入前后数量、单号、制度版本与错误解释。

## 验收

一次新建与一次重放均有真实输出，重复记录未增加。学生能指出校验由哪一层执行，并说明本地单进程实验没有证明分布式事务或生产授权。
