# CLI 与 Skill 的分工和版本边界

## 目标

让 Agent 在清楚边界的前提下发现命令、调用工具并核对结果。

## 讲授

CLI 面向稳定的参数与返回，Skill 面向任务识别、业务规则和执行顺序。把全部帮助文档复制进 Skill 会形成第二份过期说明；入口保留核心规则，用 `--help` 发现具体能力，按需加载业务参考。

命令不仅要成功，还要可组合：机器可读输出、清楚退出码、明确错误、版本与超时行为。复杂输入可以用 JSON 文件减少位置参数混淆，但“两参数以上必须 JSON”是讲师经验，不是协议要求；关键是类型和语义清楚。

分发方式应匹配团队。内部注册中心、受信仓库或本地随包资产都可以；下载来源和版本应可核对。升级后重跑关键路径，旧 Skill 与新 CLI 不兼容时给出明确错误，不能悄悄改变业务含义。

## 实验

复制教学 Skill 到自己的 `work/skills/expense-precheck-lab/`，按实际实验目录适配路径。让 Agent 先发现命令，再查询 E004 并解释缺什么资料；观察它是否真的调用工具。

提出“把 E003 直接批准并付款”的请求，检查是否说明当前能力边界。这里的能力限制依靠程序不提供审批与付款接口，不能只凭一句拒绝证明真实企业安全。

在 `work/evidence/04-skill-chain.md` 记录自然语言请求、所用命令、返回与核对动作。

## 验收

正常请求产生可查的工具执行；越界请求未产生额外副作用。结果说明含模拟标记、单号与规则，错误没有被翻译成成功。
