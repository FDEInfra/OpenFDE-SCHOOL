# ⑤ Evals 与从 Demo 到企业生产

状态：beta（大纲已整理，课节待蒸馏）

来源：OpenFDE ✖️ 观猹 FDE 共学营第 5 课，视频全长 01:54:11。[在线观看](https://openfde.net/zh/resources/guancha-fde)

## 唯一承诺

学生上完这门课，能接受「AI 应用反复出问题、反复改是常态」这一前提，并用评测驱动开发（EDD）的方法——先做 MVP、围绕 MVP 建评测集、评估整条运行过程而非单点输入输出、持续迭代测试集本身——把一个 Demo 逐步推向可验收的企业生产环境。

## 小作业（课程原题）

本节未布置新的小作业。逐字稿中主持人仅提到「补了作业可以给助教看」「作业只能用电脑吗？电脑会更方便一点」「今天晚上记得做作业」，均指共学营既有的小作业/大作业；课末提醒「大作业目前如果现在开始做的话，还有三天的时间」。两位讲师在讲课和 Q&A 中均未布置本节专属作业。

## 关键事实锚点

- 评测驱动开发 EDD（Evaluation-Driven Development）：评估从后置的质量保证环节变成开发的主控回路，先快速做 MVP 再围绕它测试（00:18:55）。
- 「测试只能证明 bug 存在，不能证明 bug 不存在」——软件开发的经典理论被直接引入 AI 应用开发（00:10:48）。
- 评估时间约占工作量 80%：「你要把百分之八十的测试时间理解成一件很正常的事情」（01:05:02）。
- 评测对象是整条运行过程（对话、环境、Runtime、记忆检索、每次 Function Calling），不是单点输入输出（00:30:20）。
- 评测集青春版四类任务：能直接回答、需要澄清、能答一半、不能回答（00:32:01）。
- LIGO「Big Dog」盲注入事件：人为注入假引力波信号，检验团队发现能力与论文/同行评审流程中的错误（00:39:26）；讲师复刻此法改坏数据库测试 Agent，Agent 未能发现（00:42:24）。
- SKILL.md 的第一行 name、第二行 description 使 skill 极易被训练管线捞出，默会知识会作为最高级别训练数据流走（00:55:27）。
- AI 安全是蓝海；沙箱方向国外做得最好的是 E2B（00:51:04）。
- MemU：开源 Agent Memory 项目，帮每个 Agent 记住用户、构建个人 LLM Wiki（概念来自 Andrej Karpathy），可在 Codex、Claude Code、WorkBuddy 等中一句指令安装（01:17:16）。
- FDE = 咨询 + 外包，词源 Palantir；FDE 公司的护城河是品牌，OPC（一人公司）接小单可以但难以规模化（01:23:24、01:34:09）。

## 完成证据（课节蒸馏后生效）

- 完成小作业并可展示产物；
- 能用自己的话复述本课核心方法论；
- 能为自己的 Agent 项目写出 MVP 契约五要素（干什么、完成标准、禁区、可用工具、需人类批准项），并搭出一个覆盖四类任务（能答/需澄清/答一半/不能答）的青春版评测集，说明评测对象是整条运行过程而非单点输入输出。
