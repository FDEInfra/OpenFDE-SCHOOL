## 唯一承诺

上完这门课，你能判断一条线索是不是值得打的 FDE 项目，把客户口中"想上 AI"诊断成一份可验收、可控变更的 SOW（项目需求说明书），并用 CLI 开发工作流（Claude Code / Codex）做出一个能证明核心价值、打动客户的企业 Agent Demo。

## 小作业（课程原题）

本节有布置小作业（01:07:38–01:09:24），讲师原话要点：

> "大家可以去认领一些小作业的业务命题，比如说去做一份 SOW 是怎么样的，然后去通过 CLI 去跑通我们这个核心业务流流程的企业 Agent 的原型。不管是通过我们刚刚讲的开源的这个项目（ChatDemo）去做，还是自己通过 Codex 或者 Claude Code，再跟客户收集完客户的需求然后来做。……能够在现场给到客户一个 Demo，当然是更好。这也是一个作业，大家可以自行斟酌，选择来做这样一份作业。"

即：认领一个业务命题 → 写一份 SOW → 用 CLI 工作流（Claude Code / Codex，可用开源工具 ChatDemo）跑通核心业务流的企业 Agent 原型 Demo。主持人在结尾（02:37:12）提醒"助教已在群里提醒大家做作业"。

## 关键事实锚点

- SOW = 项目需求说明书，作为合同附件；73% 失败的企业 AI 项目源于事先没定义好 SOW（00:19:07、00:31:29）
- FDE 铁三角：商务型（销售/售前/客户成功）+ 产品型（项目经理/设计/Demo）+ 工程型（算法/研发/测试）（00:18:26）
- 定价参考线：最小三人铁三角，5–6 万项目只覆盖成本，10 万级才有合理利润（00:28:54）
- 国企项目利润率约为私企外企两倍，但验收难、易烂尾（00:30:57）
- 斯凯奇案例：AI 套板准确率 85%→95%，一个月交付，下一季度迁移安踏（00:43:37、00:47:56）
- 一人并发带 agent 上限 3–5 个（to B 场景）（00:56:04）
- 银行信用卡 AI 客服：agentic RAG + 意图槽位，准确率 70%→95%，历时约一年（01:00:20、02:04:32）
- 开源工具 ChatDemo（GitHub 可搜）：边和客户聊边录音转写并生成 Demo（01:05:10）
- 付款惯例：三期为主（签约 15–30% / 上线 30–50% / 验收结清），极端五期，留 5–10% 质保金并约定 SLA 与 P0/P1 事故扣款（01:26:53–01:29:25）
- SOW 黄金标准：客户能签字且你一定能做到；未被验证的指标能不写就不写、能往低写就往低写（02:34:23–02:36:41）
