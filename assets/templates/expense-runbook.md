# 报销预审运行与移交

## 启动与验证

从学校根目录读取 `references/lab-guide.md`，按指南在新工作目录初始化，先运行离线评测，再启动本机模拟服务。另一个终端读取单据与 E003，确认预审为超标转人工。

运行 `python3 scripts/validate_lab.py` 检查业务与 HTTP 行为。该脚本用临时目录和随机本机端口，不依赖已运行的服务，不修改学员工作数据。

## 处理异常

- 连接失败：确认服务终端、端口与路径，不能直接重写业务数据；
- 401：检查教学标记是否设置在发请求的终端，日志不回显凭证；
- 404：核对单号与当前工作目录；
- 409：核对幂等键、当前制度与已有记录，不换键强行制造第二条复核；
- JSON 无法解析：保留原文件，检查修改来源，再从有记录的副本恢复；
- 制度变化：停止服务，备份实验状态，修改明确的制度，重启并重跑回归。

## 停止与恢复

在服务终端按 Ctrl+C 停止。重启使用原工作目录，复核记录与幂等信息会保留。需要从头练习时建立新目录，不覆盖旧证据。对单个业务动作重试时沿用原幂等键。

## 移交检查

接收者应知道工作目录、启动命令、规则版本、评测报告、日志位置和已知限制。由其实际完成一次读取与异常定位，记录真实卡点；未完成独立操作时不能填写“移交验证通过”。

本项目是教学模拟，无真实身份系统、数据库事务、备份服务、生产监控与高并发保证。进入真实试点前另行确认责任人、数据授权、权限、密钥管理、负载、观测、恢复与业务复核。
