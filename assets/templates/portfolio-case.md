# 报销预审与人工复核案例

## 业务背景与问题

本例采用模拟财务场景。目标是减少票据、金额与制度的重复核对，将缺资料与风险分流给人，不替代财务审批。没有真实客户访谈的部分保持教学设定。

## 范围与个人贡献

说明本人实际完成的诊断、规则、接入、评测或文档，并区分 AI 辅助生成、团队贡献和自己做出的判断。没有完成的内容不列入经历。

## 方案与取舍

规则校验用确定程序，本机 HTTP API 提供系统入口，CLI 执行查询和受控写回，Skill 组织任务与结果解释。金额使用整数分，缺资料不猜测，重复风险交人工。真实 OCR、ERP、企业认证与付款不在本例范围。

## 可验证结果

以本人保存的实际评测、运行输出与日期为依据，分别记录样本数、通过数、失败数、环境错误、制度与程序版本。配套当前版本的预期为 12 条虚构用例通过；未实际运行时只能写预期，不能写成自己的结果。

## 一次失败与复盘

可使用预置边界故障说明诊断：限额比较把等于也当成超标，C002、C011 应能暴露它。预置版本切换不能冒称自主修复；自己的新增用例、代码改动与验证另附证据。

## 局限与下一步

模拟数据不能估计真实财务准确率；没有真实采用与基线，不能声称已节省客户成本。下一步可验证业务规则、真实脱敏样本、权限与使用者反馈。公开展示前检查客户与个人信息、截图、凭证和授权。

## 三种表达

长文保留完整背景、判断和失败；README 提供业务摘要与复现方式；一页摘要保留问题、本人贡献、证据、边界与下一步。三种版本使用相同事实与数字口径。
